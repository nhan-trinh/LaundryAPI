# Domain docs

Before exploring an area, read the root `GLOSSARY.md` and any relevant
architecture decision records in `docs/adr/`. If either is absent, continue
with the task. The `domain-modeling` skill creates these docs as terms and
decisions are agreed.

Use glossary terms in issues, proposals, and tests. If a concept has no entry,
check the project's existing language and flag genuine gaps for `domain-modeling`.

If a proposal conflicts with an ADR, cite the decision and explain why it
should be revisited.
